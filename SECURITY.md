# Security reports

Use GitHub's private vulnerability reporting when available. Otherwise open an issue describing the impact without credentials, private form links, response data or file paths, and request a private channel before sharing sensitive details.

Use the current GitHub build for unreleased fixes. Saved responses and run logs contain plaintext answers; keep them in a private directory. Do not commit cookies, browser profiles, credentials or real response data.

AI generation sends form text, user instructions and reference examples to ChatGPT in a private browser. Image and video metadata stays in form inspection. Any details entered in extra instructions are sent as text. The private session can require manual sign-in or verification. Supplied-data HTTP submission runs independently of ChatGPT.

Known secret URL parameters are redacted in outgoing AI prompts, including corrections; embedded credentials and account/edit-response links are omitted. This is not a general secret detector. Local configurations and prepared response files retain original metadata and supplied answers in plaintext so saved identities and submission recovery remain intact. These files are not encrypted. AI generation keeps progress in memory only; old checkpoint files remain untouched. ChatGPT output passes local form validation before use, but validation does not establish factual correctness.

Native wheels vendor selected upstream Selenium files. Updates must verify the pinned recipe, upstream advisories, preserved notices, installed-wheel checks and browser tests; dependency alerts do not update that bundled runtime automatically.

The response editor is a temporary server bound to 127.0.0.1 with a random session URL, same-origin save checks, no-store responses and a restricted content policy. It sends no data to AI or Google. Saved edits keep batch identities and cannot reset submitted or uncertain outcomes. It closes on Done, terminal Ctrl+C or an idle timeout.
